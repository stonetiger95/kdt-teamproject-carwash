# 나의 역할과 기여

## 역할 요약

**번호판 데이터를 선별하고 OCR 모델을 학습·비교·선정한 뒤, AI API와 차량 입출차·관리자 검수 흐름까지 연결했습니다. 예지보전 기능에서는 모델 실험 결과를 검토해 운영 목적에 맞는 모델을 선정하고 서비스 통합을 담당했습니다.**

## 담당 영역

| 영역 | 역할 | 주요 기여 |
|---|---|---|
| OCR 데이터 | 담당 | 공개 번호판 데이터 선별, 실사 데이터 분리, 학습·검증·locked test 구성 |
| 번호판 탐지 | 담당 | Roboflow bbox 데이터 학습, 실환경 실패 732장 재라벨링과 Hard Sample 재학습 |
| OCR 모델 | 담당 | CRNN·CNN-only 구조 비교, Lite075·Lite050 경량화, decoder 실험과 최종 모델 선정 |
| AI 서비스 연동 | 담당 | FastAPI–Spring 요청·응답 구조 설계, 이미지 전송과 결과 저장·차량 흐름 연결 |
| OCR 검수·환류 | 담당 | 문자열·bbox 교정, 학습 후보 승인, 이미지·CSV·JSONL Export 흐름 구현 |
| 차량 상태 제어 | 담당 | 장비 검증, 중복 입차 방지, 세차·결제 미완료 출차 제한과 통합 테스트 |
| 차량 관리 | 담당 | 차량 등록·논리 삭제, 중복 번호판 처리와 블랙리스트 연동 |
| 예지보전 | 담당 | 모델 실험 검토, L2 로지스틱 회귀 선정, FastAPI·Spring·관리자 화면 통합 검증 |
| 예약·결제·관리자 UI | 공동 구현 | OCR 입차 및 차량 상태 흐름과 연결하고 후반 통합 오류와 UI 보완 |

## 1. OCR 데이터와 모델 개발

- AI Hub 90,000장 가운데 1줄·7~8자리 정규 번호판 61,922장을 선별해 학습 55,730장과 검증 6,192장으로 구성했습니다.
- 광안대교 실환경 10,000장은 학습 8,100장, 검증 900장, 모델 선택에 사용하지 않는 locked test 1,000장으로 분리했습니다.
- Roboflow 번호판 bbox 데이터는 OCR 문자 학습 데이터와 분리해 YOLO 탐지 학습에 사용했습니다.
- 실환경에서 탐지에 실패한 732장을 직접 재라벨링해 Hard Sample로 재학습했습니다.
- CNN-only Base가 CRNN보다 무거워진 원인을 채널 수에서 찾고 Lite075·Lite050으로 재설계했습니다.
- Greedy, Beam 5·10과 번호판 형식 우선 선택을 비교해 Lite050 + Beam5/Format을 최종 조합으로 선정했습니다.
- OCR 전용 실사 Crop locked test 1,000장에서 문자열 완전 일치 97.1%를 확인했습니다. 이 수치는 YOLO 탐지부터 포함한 end-to-end 정확도가 아닙니다.

## 2. OCR을 운영 흐름으로 확장

- FastAPI와 Spring Boot 사이의 이미지 요청·OCR 응답 계약을 설계하고 구현했습니다.
- OCR 결과를 차량 등록, 예약 확인과 입차 처리에 연결했습니다.
- 원본 예측, confidence, 이미지와 bbox를 저장해 실패 원인을 추적할 수 있게 했습니다.
- 관리자가 번호판 문자열과 bbox를 독립적으로 수정하고 승인된 항목만 후속 학습 자료로 내보내도록 구현했습니다.

## 3. 입차·세차·출차 상태 보호

- 요청 장비의 유형과 활성 상태를 OCR 호출 전에 검증했습니다.
- 동일 차량이 반복 감지되면 열린 입차 기록을 재사용해 중복 생성을 막았습니다.
- 예약 차량의 배정 세차기와 실제 요청 장비가 다르면 올바른 장비로 안내했습니다.
- 세차 완료와 결제 완료를 모두 확인한 뒤 출차가 가능하도록 했습니다.
- 서비스 트랜잭션과 DB 조건부 갱신을 함께 사용해 잘못된 상태 전이를 차단했습니다.

실제 차단기와 세차장 장비는 연결하지 않았으며, 웹 화면과 API 요청으로 장비 이벤트를 시뮬레이션해 소프트웨어 동작을 검증했습니다.

## 4. 예지보전 모델 선정과 통합

고장 라벨이 적은 프로젝트용 합성 센서 데이터에서 로지스틱 회귀 v1·v2와 OCSVM 보조 후보를 검토했습니다. 재현성, 설명 가능성, 확률 보정과 운영 편의성을 고려해 13개 특징을 사용하는 L2 로지스틱 회귀를 선정했습니다.

- 개발환경 PR-AUC: 0.2136 → 0.2680
- 고장 사건 탐지: 5건 중 3건 → 4건
- 오경보: 장비·월 6.24건 → 3.47건
- FastAPI 추론 결과와 Spring DTO·저장 로직의 입력·출력 정합성 검수
- 운영·시연 모드, shadow prediction, 알림과 로그 흐름 통합 확인

이 결과는 에스트래픽 실무 담당자가 프로젝트용으로 제공한 합성 데이터에 대한 개발환경 검증이며 실제 장비 운영 성능을 의미하지 않습니다.

## 협업 범위

결제, 지도, 소셜 로그인, 정산과 혜택은 다른 팀원이 중심적으로 구현했습니다. 예약·비회원 결제·관리자 통합 화면은 공동 작업이었으며, 이 포트폴리오에서는 해당 기능 전체가 아닌 OCR 입차·차량 상태 흐름과의 연동 및 통합 검증 범위만 개인 기여로 설명합니다.

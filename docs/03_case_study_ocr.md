# 문제 해결 사례 1: 실사용에 강한 OCR 모델 선택

## 한 줄 요약

구조화된 번호판 문자열에는 RNN의 문맥 모델링이 필수적이지 않다는 가설로 CNN-only 모델을 구현했으나 예상보다 무거워지는 문제를 발견했다. 채널 폭을 75%·50%로 재설계하고 실사 locked test를 비교해 Lite050을 최종 배포 모델로 선택했다.

## 1. 문제

번호판 OCR 모델을 서비스에 적용하려면 단순히 validation 정확도가 가장 높은 모델을 선택하는 것으로 충분하지 않았다.

- 공개 데이터와 실제 카메라 이미지의 촬영 조건이 달랐다.
- 7자리와 8자리 번호판의 난이도 차이가 컸다.
- YOLO 자동 크롭과 수동 교체 크롭이 함께 존재했다.
- 모델 정확도뿐 아니라 크기와 decoder 비용도 고려해야 했다.
- 반복 실험 과정에서 test 데이터를 기준으로 설정을 바꾸면 성능을 과대평가할 위험이 있었다.

## 2. 데이터와 평가 기준 고정

먼저 AI Hub 90,000장과 광안대교 실환경 10,000장의 데이터 풀에 대해 파일 존재 여부, 이미지 디코딩, 라벨 길이와 출처를 감사했다. 100,000장을 모두 OCR 학습에 사용한 것은 아니며, 1차 서비스 범위인 1줄·7~8자리 정규 번호판만 선별했다.

| 데이터 | 수량 | 용도 |
|---|---:|---|
| AI Hub 전체 데이터 풀 | 90,000장 | 감사·선별 대상 |
| AI Hub 1줄·7~8자리 선별 데이터 | 61,922장 | 학습 55,730장·검증 6,192장 |
| 광안대교 실환경 데이터 | 10,000장 | 학습 8,100장·검증 900장·locked test 1,000장 |
| 실사 locked test | 1,000장 | 최종 선택 |
| YOLO 자동 크롭 | 9,764장 | 실사 OCR 입력 |
| 수동 교체 크롭 | 236장 | 탐지 실패·오류 보정 |

Roboflow 데이터 약 10,000장은 OCR 문자 학습 데이터가 아니라 번호판 위치를 찾는 YOLO bbox 학습에 별도로 사용했다. 이후 실환경에서 탐지·Crop에 실패한 732장을 직접 재라벨링해 Hard Sample로 추가하고 YOLO를 재학습했다.

2단 번호판과 지역명이 포함된 장문 번호판은 단일 OCR 모델의 1차 서비스 범위에서 제외하고 향후 과제로 남겼다.

locked test 1,000장은 **OCR 문자열 인식 평가용 번호판 Crop 데이터**다. 모델 학습뿐 아니라 scaler, PCA, KMeans 품질 군집 학습에서도 제외했으며, 최종 평가 전까지 모델 선택 기준으로 사용하지 않도록 분리했다. 따라서 이 결과는 YOLO 탐지부터 포함한 end-to-end 번호판 인식 정확도가 아니다.

YOLO는 제한된 프로젝트 학습 시간으로 실환경 Crop 오류가 남았다. 다만 목표 서비스인 세차장은 광안대교 도로 영상보다 차량 위치·거리와 촬영 방향을 일정하게 통제할 수 있다는 운영 가정을 두었기 때문에, 프로젝트에서는 OCR 일반화와 서비스 흐름 구현을 우선했다. 남은 탐지 오류는 관리자 bbox 교정, 오류 유형 기록과 재학습 후보 Export를 통해 후속 개선할 수 있도록 설계했다.

평가 지표:

- 번호판 전체 문자열 완전 일치율
- 문자 정확도와 CER
- 7자리·8자리 번호판별 정확도
- 품질 군집별 정확도
- 모델 파라미터 수와 파일 크기
- CPU/GPU 추론 및 decoder 지연시간

## 3. 입력 규격과 기준선 설계

번호판 비율을 유지하는 padding과 직접 resize를 비교했다. 공개 데이터에는 세로 비율이 큰 번호판이 포함되어 있어 padding 사용 시 문자가 지나치게 작아졌다.

첫 입력 규격은 다음과 같이 고정했다.

```text
원본 번호판
  → grayscale
  → 48×192 직접 resize
  → -1~1 정규화
  → CNN/CRNN
  → CTC logits [T=24, B, 55]
```

- 학습 문자: 54종
- 출력 클래스: 54문자 + CTC blank
- 정답 길이: 7자 또는 8자
- 좌우 반전 증강 금지
- 밝기·대비, 약한 blur와 noise만 적용

32장 과적합 실험에서 초기 CTC blank 붕괴를 확인한 후 시간축을 48에서 24로 조정하고 blank logit 초기 bias를 낮췄다.

## 4. CNN-only 가설과 예상 밖의 결과

번호판은 일반 문장과 다른 구조를 가진다.

- 문자열 길이가 7자 또는 8자로 제한된다.
- 숫자와 한글의 위치 패턴이 비교적 일정하다.
- 자유로운 자연어처럼 긴 문맥을 이해할 필요가 적다.

따라서 CRNN의 BiLSTM이 제공하는 순차 문맥 정보가 번호판 인식에 반드시 필요한지 의문을 가졌다. 이를 확인하기 위해 BiLSTM을 제거하고 CNN encoder의 가로축 특징을 1×1 convolution classifier와 CTC에 직접 연결한 `PlateCNNCTC`를 구현했다.

```text
CRNN       : CNN → BiLSTM → Linear → CTC
PlateCNNCTC: CNN → 1×1 Conv Classifier → CTC
```

처음에는 RNN을 제거하면 모델도 자연스럽게 가벼워질 것으로 예상했다. 하지만 실제 파라미터를 측정하자 결과는 반대였다.

| 모델 | 파라미터 |
|---|---:|
| CRNN | 2,355,447 |
| PlateCNNCTC Base | 4,529,655 |
| Lite050 | 1,140,503 |

BiLSTM을 제거했지만 Base CNN encoder의 채널 수가 커서 CNN-only 모델이 CRNN보다 약 1.9배 무거웠다. 문제는 `CNN-only 가설` 자체가 아니라, 가설을 처음 구현한 모델의 채널 설계였다.

이를 해결하기 위해 Base 모델의 채널 폭을 비율로 줄이는 `width multiplier`를 적용했다.

- Lite075: Base 채널 폭의 75%
- Lite050: Base 채널 폭의 50%
- 각 채널은 연산 효율을 고려해 divisor 8 단위로 조정

이 실험을 통해 RNN 제거 여부와 모델 경량화를 별개의 설계 문제로 다뤘다. 최종적으로 Lite050은 CRNN의 약 48%, PlateCNNCTC Base의 약 25% 수준까지 파라미터를 줄였다.

## 5. 모델 비교

동일한 manifest와 평가 코드를 사용해 다음 구조를 비교했다.

- CRNN
- STN-CRNN
- PlateCNNCTC Base/Deep/Context
- Lite075/Lite050
- PaddleOCR
- PARSeq

validation 900장에서는 STN-CRNN이 가장 높은 결과를 기록했다.

| 모델 | Validation 완전 일치 |
|---|---:|
| STN-CRNN | 893/900, 99.22% |
| Lite050 | 890/900, 98.89% |

validation만 보면 STN-CRNN이 우선 선택이었다. 하지만 최종 locked test에서는 결과가 역전됐다.

| 모델 | Locked test | 7자리 | 8자리 |
|---|---:|---:|---:|
| STN-CRNN | 937/1,000, 93.7% | 96.54% | 83.64% |
| Lite050 + Beam5/Format | 971/1,000, 97.1% | 96.92% | 97.73% |

STN-CRNN은 특히 8자리 번호판에서 성능이 크게 낮아졌다. Lite050은 validation 점수는 조금 낮았지만 실사용 분포의 locked test와 8자리 번호판에서 훨씬 안정적이었다.

## 6. Greedy 정확도 한계와 decoder 탐색

Lite050의 Greedy decoding 결과가 목표에 미치지 못해 단일 최고 확률 경로만 선택하지 않고 여러 CTC 후보를 유지하는 Beam Search를 비교했다. 전처리는 baseline, gamma 0.8, CLAHE를 비교했고 decoder는 다음 조건을 평가했다.

- Greedy
- Beam Search 5
- Beam Search 10
- Beam Search 5 + 번호판 형식 우선 선택
- Beam Search 10 + 번호판 형식 우선 선택

Corrected-v2 validation 900장 결과:

| Decoder | 완전 일치 | Greedy 오답 복구 | Greedy 정답 훼손 |
|---|---:|---:|---:|
| Greedy | 887/900, 98.56% | - | - |
| Beam 5 | 887/900, 98.56% | 0 | 0 |
| Beam 10 | 887/900, 98.56% | 0 | 0 |
| Beam 5 + Format | 890/900, 98.89% | 3 | 0 |
| Beam 10 + Format | 890/900, 98.89% | 3 | 0 |

Beam Search만으로는 Greedy 대비 정확도가 개선되지 않았다. 여러 후보 중 한국 번호판 형식에 맞는 결과를 우선 선택했을 때 오답 3건이 복구되었고 기존 정답은 훼손되지 않았다.

Beam 5와 Beam 10의 정확도가 같았기 때문에 불필요하게 탐색 폭을 늘리지 않고 Beam 5를 선택했다. 전처리 실험에서도 gamma와 CLAHE가 Lite050의 완전 일치율을 개선하지 못해 baseline 전처리를 유지했다.

이 결과를 통해 `복잡한 decoder가 항상 더 정확하다`고 가정하지 않고, Beam Search와 도메인 형식 규칙의 효과를 분리해 판단했다.

## 7. 최종 결정

최종 모델은 **Lite050 + CTC Beam Search 5 + 번호판 형식 우선 선택**으로 결정했다.

선택 이유:

1. 실사 locked test 완전 일치율이 3.4%p 높았다.
2. 8자리 번호판 정확도가 약 14.09%p 높았다.
3. 파라미터가 1,140,503개로 STN-CRNN보다 작았다.
4. 형식 우선 decoder가 번호판 후보 선택에 유효했다.

단, 경량 모델이라고 해서 전체 파이프라인이 항상 빠른 것은 아니었다. Lite050의 Beam Search와 형식 검증은 STN-CRNN의 greedy decoder보다 계산 비용이 컸다. 따라서 Lite050의 장점은 속도가 아니라 더 작은 모델 크기와 실사 일반화 성능으로 평가했다.

## 8. 결과

- OCR 전용 실사 Crop locked test 1,000장 완전 일치: **97.1%**
- 문자 정확도: 약 **99.07%**
- CER: 약 **0.93%**
- 8자리 번호판 완전 일치: 약 **97.73%**
- 모델 파라미터: **1,140,503개**
- 최종 배포 조합: YOLO11s + Lite050 + Beam5/Format

후속 corrected-v2 평가에서는 97.5%가 기록되었지만 정답·크롭 교정 버전이 다르므로 배포 대표 수치와 혼용하지 않는다.

## 9. 이 사례가 보여주는 역량

- 데이터 누수를 막는 평가 설계
- validation과 실제 배포 분포의 차이를 해석하는 능력
- 정확도뿐 아니라 모델 크기·decoder 비용·오류 유형을 함께 보는 판단
- 여러 모델을 동일 조건에서 비교하는 실험 관리
- 아키텍처 구성요소 제거와 실제 경량화를 구분하는 모델 설계
- 예상과 다른 파라미터 측정 결과를 바탕으로 채널 폭을 재설계한 경험
- Greedy·Beam 폭·형식 규칙·전처리 효과를 분리한 decoder 실험
- 결과가 예상과 다를 때 validation 순위보다 실제 근거를 우선하는 의사결정
